# 以后公开仓库前的处理清单

本次交付源码包可独立运行，已按记录的export-ignore规则排除完整题面、原邮件/参考截图、私人协调材料和用户报告。当前私有Git历史保留原记录，**不能据此直接认定原仓库已经适合切为public**。P2未改变可见性、创建替代公开仓库、删除远端引用或重写历史。

## 已核对与未覆盖

审阅已检查当前分发树、当时全部本地可达refs及其历史，记录已知题面截图、邮件参考图和本地绝对路径。有限的GitHub token/私钥等高置信模式未命中；这只说明这些模式在当时扫描范围的结果，不等于完整秘密审计。不可达对象、未拉取远端分支、PR缓存、Actions产物、Release附件、其他fork和下载副本未被清除，也没有据此声称全部不存在。

保留的React Bits Orbit适配含MIT与Commons Clause完整附加条件，原创MIT不覆盖第三方。照片/衍生遵循各自Unsplash许可，吴云画作资源有The Met公开领域/CC0来源；公开前继续保持NOTICE和原许可，不能把全仓统一重新授权为纯MIT。

## 保留原仓库时

1. 先私下备份原始私有仓库和全部refs，冻结准备公开的版本，收集远端branches/tags/PR、Actions/Release附件的完整清单。
2. 明确哪些原题/邮件资料可以公开；无必要的资料和绝对路径按已知路径与内容查历史，而非只删HEAD。若发现真实凭据，先撤销/轮换，再处理历史。
3. 历史重写、删除远端refs、强推和缓存处理须在用户另行授权后执行，通知协作者并按GitHub相应流程处理受影响缓存；P2不执行这些操作。
4. 在新的镜像克隆中复扫全部refs/历史及打算分发的附件，重建本项目并对比业务源码、素材和许可；保留SHA映射与审计结论。确认旧refs/附件处理完成再由用户改可见性。

也可以在另行授权后，从本次已过滤且核过hash的源码快照建立新的公开发布仓库，保留原研发历史私有。这是可选发布方式，本轮没有创建或推送该仓库；单在原仓库新增orphan分支不会隐藏其他历史，不能作为替代清理。

## 可保持的内容

完整前后端、测试、Compose/CI/锁、迁移/种子、合法本地素材和来源许可、准确README与脱敏验证结论应继续保留。个人报告、原始运行视频、真实上传/数据库/备份、cookie/password/storage-state和未脱敏聊天不随公开版本传播。最终公开动作与考试交卷是两件事，当前源码包不自动授予任何仓库外资料公开权限。
