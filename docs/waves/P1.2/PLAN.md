## 最终体验

“探索模板 → 进入制作 → 选图上传 → 受理任务 → 查看历史 → 预览结果”形成连续、有反馈的操作过程。制作页和历史页延续浅纸白、浅水墨与蓝紫细线，页内有清楚可辨的低频动态，不只在进入时闪一下。真正操作发生时才出现更强的短动画；文字、上传图与制作结果保持清晰。

- 跳转：当前模板封面自然衔接到详情示例图，新页面内容轻柔展开，返回/前进方向一致；导航与文件选择都立即执行。
- 上传：空上传位有浅网格/低频边光；点击有局部蓝紫短光点与按压，原生文件选择同步打开。选图后照片显露，上传中有真实不定量反馈，服务端就绪后描边/勾线收束；替换、移除、取消与错误各有短而明确反馈。
- 制作与历史：主操作有受理反馈，新任务在对应记录出现；阶段跟随Java真实记录变化，成功图显露、失败安静提示、查询异常保留已有记录。历史不因每轮查询反复飞入。
- 弹窗和边界：结果预览从缩略图柔和放大、关闭回位，身份弹窗同一语言；加载、空、请求异常、模板404及全站404/路由错误也有完整界面，减少动态时均可直接操作。

技术方案以现有Link+CSS/少量SVG/WAAPI完整流程为基线，React19.3/Next16.4.3原生ViewTransition为经BASE实测安全后的公共封面增强；启动时Leader补齐已核实的19.3.0开发类型并验证兼容。公共封面共享转场与所有页面的CSS入场分别设计；不支持原生转场仍有完整反馈。Motion/Aceternity是设计参考，React Bits ClickSpark/StarBorder按实际来源适配，详见references与规格。此刻没有安装或复制新运行代码。

## 多Agent与推进

| 任务 | Owner | 依赖/产物 |
| --- | --- | --- |
| P12-BASE | Leader | P1.1完整CI封存后刷新精确基准；版本/类型/来源/逐页预算与基线 |
| P12-FOUND | 唯一Frontend | BASE后，页面作用域、事件反馈与可取消视觉协调层 |
| P12-ROUTE | 同一Frontend | FOUND后，真实Link、公共封面衔接、前进返回与加载/快速切换 |
| P12-STUDIO | 同一Frontend | ROUTE后，制作场景与上传/替换/移除/提交完整状态动画 |
| P12-HISTORY | 同一Frontend | STUDIO后，嵌入/独立历史与真实任务阶段、分页与结果入口 |
| P12-DIALOG | 同一Frontend | HISTORY后，结果/身份弹窗与404/空/错误/加载覆盖 |
| P12-ACCEPT | 独立Acceptance | BASE后设计用例，DIALOG集成后签功能/资源/舒适与原业务 |
| P12-REVIEW | 独立Reviewer | 首个可运行子页后审中间产物，DIALOG后逐页签美学 |
| P12-DELIVERY | Leader | ACCEPT+REVIEW后集成完整CI、报告/源码/实际投入与回滚，然后停止 |

Leader+最多三子；本轮无新素材/后端任务。唯一Frontend顺序推进，避免多人改studio.tsx、Shell与CSS。Acceptance只写新独立验收，Reviewer只写审核报告；Leader持有依赖锁/共享CI/契约与最终集成。具体所有权见ROLES、任务包与CONTEXT-MAP。

## 启动和完成门槛

准备包、来源审计、静态动作分镜、独立准备审阅及data-only检查齐备才标准备完成；P1.1CI未收尾不能作P1.2执行基准。用户最新授权“1.2准备好了直接启动不用报告了”；独立准备审阅和检查通过后直接执行，不再等待确认。通过前不启P1.2开发worktree或依赖安装。

正式启动后先用一条真实路径验证“封面衔接+文件选择立即打开+一次上传状态”，再顺序铺到所有页面。美学须对制作/历史/弹窗/边界分别逐项≥4/5；首页静态/动态回归保持。独立舒适验收与原绝对预算同时通过才交付，不靠关闭关键效果获得绿灯。

估计6–9小时有效投入含验证/修正/交付，非已耗事实或截止承诺。执行时记录实际起止与未知人工时间；并行Agent时间不相加，同根因两次无效修复后有界重诊断。P1.2完成后停止，不自动开启下一阶段；邮件按用户要求继续暂缓。
