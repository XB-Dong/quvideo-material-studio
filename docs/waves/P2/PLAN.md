## 工作流和多Agent

Leader先逐条审REQUIREMENTS-MATRIX，给每项未满足/未验证指定task与证据要求，冻结身份/迁移/接口及owner后派发。启动后不向用户提问，按已确认目标自主决定常规方案；边界外的公开/历史重写/交卷留作用户操作清单，不借机授权执行。

第一阶段Leader持有文档/交付、Backend唯一写Java和V4、Frontend唯一写账户页面/身份生命周期、Acceptance独立准备与测试，最多三个worker。Java/前端可在冻结契约后并行。Backend释放席位后Reviewer进入，进行只读来源/历史与实现审查；产品写入停止后Acceptance独占运行窗口。Leader依据独立结果编写报告，Reviewer最终只读核对，Leader签署。无需常驻额外Docs/Asset角色。

原题截图和邮件图不作为项目原创素材重新许可。默认将完整题面/参考附件和内部用户报告保留为用户私有材料；公开版仅保留自己撰写的项目说明、必要R编号、合法素材及脱敏证据。若原历史含需排除内容，仅删HEAD文件不足以准备原仓库转公开；报告给出原仓库历史处理与干净快照方案，实际破坏性操作须另获授权。
