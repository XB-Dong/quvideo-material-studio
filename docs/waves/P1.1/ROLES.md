# P1.1 多Agent角色与所有权

一名Leader，最多三名活跃子Agent；不创建用户侧新聊天，继承当前模型/推理，实际路由无证据保持null。准备审阅已结束，用户明确启动后，按下表派发独立开发worktree；最多三子Agent。

| 角色 | 任务/独占路径 | 交付 |
| --- | --- | --- |
| Leader | BASE、CI-MAIL、DELIVERY；specs/p1.1、根导航/状态、依赖锁、CI/Compose/集成/邮箱规则 | 冻结SHA与契约，按已确认仓库作用域处理通知，集成/最终报告 |
| 唯一Frontend | BRAND→SCENE→CARDS顺序；frontend/src/app/globals.css、app/layout.tsx、components/shell/catalog/studio/history、creative/motion、providers仅动效包装、public/icon.svg及自身测试 | 疏影、去按钮、擦雾/多边框、真实卡片效果和生命周期 |
| Asset | ASSET；frontend/public/ink/**、assets/p1.1/**转换脚本、专属来源/衍生证据 | 本地背景、合法来源/哈希、预算与复现；不写globals/Shell/icon，不改旧图/Java |
| Test/Acceptance | ACCEPT；tests/p1.1/**及显式共享测量helper转交、独立evidence/handoff | 正常软件真实动效、全图片成本、功能/P0/通知作用域与独立舒适签署 |
| Reviewer | REVIEW，Asset释放席位后；分配的reviews文件，代码只读 | 真实页面/动态五维美学、问题与复验；不得替作者自测签独立通过 |

并发R1为Frontend+Asset+Acceptance；释放Asset后是Frontend+Acceptance+Reviewer。Frontend共享文件始终唯一作者；Leader单写package/lock和CI，需求改变先更新契约/owner。Acceptance不改产品或原作者测试，不因去gallery而删除业务验收。

保护frontend/src/lib/api.ts、types.ts、use-tasks.ts、session-generation.ts及原业务测试，QueryClient/Identity实例稳定。无后端/数据库改动计划；若确有必要，先独立记录消费者与路径转交。任务包基准是P1封存e485，启动时Leader复核最新可达SHA后再派发。准备文件不授权运行。
