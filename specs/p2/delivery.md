## 用户报告每条格式

官方编号与要求摘要 → 我们如何满足 → 精确文件/符号 → 运行/测试与SHA/时间/环境/结果 → 限制/未验证 → 结论/待办。R-13九条分别是版本结构连接命令、配置初始化素材、接口状态执行、成功失败耗时多任务刷新、身份、完成限制投入重启、部署回滚、AI工作流、来源复用。附全局验收SHA、ZIP名/哈希和证据索引。

状态使用：已实现且当前候选已验证 / 已实现且仅历史版本已验证 / 源码已实现但当前未验证 / 未实现 / 环境阻塞 / 原题非要求。准备报告不得使用“最终全部通过”；公开问题单列，不包装为必需业务缺陷。

## 提交物与用户私有材料

招聘方：源码ZIP为默认主交付，`提交说明.md`可直接贴原沟通渠道；可附repo链接及验收40位commit。无需公网地址、部署截图、数据库备份、聊天记录、账号或付费资源。用户报告默认给用户看，不自动作为招聘方附件。

招聘方展示附件按用户要求包含首页山水交互.gif与制作与历史流程.gif，实际录制规范见MEDIA，附件计数与ZIP/文本说明一并核对。

用户：逐条符合性报告、提交物清单及SHA256 manifest、公开准备审计/待处理清单。可以提供合适的文件链接，不强制PDF/视频，不增加无用附件。

最终清单字段：repository、deliveryCommit、testedProductCommit、ciRuns（准确SHA/url/conclusion）、productTreeEquivalence（若不同commit）、generatedAt、files（name/role/bytes/sha256）、checks、limitations、mailStatus、submissionStatus。清单在最终ZIP外生成以避免“ZIP含自身哈希”和“提交含自身SHA”的循环；压缩包内可含源码版本说明，用户外部清单绑定最终文件。

产品源码/配置/依赖/SQL/素材/CI/测试变更后须重跑受影响与必需完整检查。仅报告文档封存与验收源不同，必须明确各SHA，核对可执行树完全相同；最终push的CI仍照常执行，不加skip-ci、不删检查。最后一次CI结果可在仓库外清单记录，不为回填结果无限制造新commit。

## 执行环境与隔离

安装、构建、测试、应用执行全部在容器；宿主仅Git、文档、数据核对和打包操作。独立Compose项目名与端口在BASE冻结，产品3000和现有卷保留。ZIP从精确版本生成、解压到仓库外新目录，不带.git/依赖缓存/运行数据。测试只用合成身份/fixture，不把cookie、用户上传或未脱敏原始trace提交进Git/附件。

## 许可和公开边界

拟对原创代码选择MIT并清晰列例外，P2-AUDIT核对后由Leader落地；准备时不添加授权文件。React Bits当前本地许可为MIT+Commons Clause，不能称纯MIT，也不能以根MIT覆盖。需核对冻结许可、实际挂载与保留独立组件、应用源码分发方式。不能确认时如实阻塞公开准备结论，采用明确许可/有据清理未用代码/合规等价实现等有界方案；不自动改已认可页面。

公开不等于向评估者保证私库可访问。默认ZIP解决本次读取；原仓库以后改public必须处理历史披露面，任何history rewrite/force-push/可见性变更均非本轮授权。
