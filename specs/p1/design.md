# P1 视觉设计规格

版本P1-1.2.0。方向：浅色留白创作台。以瓷白背景、白色面板、炭灰文字形成干净层次；蓝紫用于线条、边框、图标、选中态和少量操作强调，图片成为视觉重点。参考选择与本地素材见 docs/waves/P1/references/README.md；可视提案见该目录direction-board.svg。

## 设计 token

| Token | 值 | 用途 |
| --- | --- | --- |
| background | #F7F8FC | 中性瓷白页面底色，避免整页蓝紫染色 |
| surface | #FFFFFF | 卡片、制作/历史/弹窗大面板 |
| surfaceSubtle | #F0F2F7 | 输入底、次级分区和低对比骨架 |
| text | #202433 | 炭灰正文与标题 |
| textMuted | #626B7C | 辅助文字和描述 |
| accentBlue | #4F63D8 | 细线、图标及单个主按钮的小面积实色 |
| accentPurple | #7961C5 | 选中线条、局部边缘与细节呼应 |
| accentInk | #4654B4 | 链接、选中项文字和键盘focus |
| accentSoft | #F3F2FC | 小面积选中底纹，不用于页面/大面板铺底 |
| border | #E2E5ED | 装饰分隔与卡片细边，不承担唯一操作边界 |
| controlBorder | #818C9F | 必须可辨的输入边界；与相邻底色核验≥3:1 |
| success / danger / warning | #237452 / #B83952 / #856220 | 浅色背景上的状态文字，搭配图标/文案 |

底色和大面板以瓷白、纯白、浅灰构成层次，图片提供主要色彩，蓝紫出现在1px细边/分隔线、图标、选中下划线与少量动作强调。键盘focus用清晰2px轮廓，不受装饰细线限制。避免大面积蓝紫填色、整页渐变、深色玻璃和霓虹光污染。

主按钮可用accentBlue小面积实色配白字；次按钮白底细边、文字保持炭灰/强调色。蓝→紫渐变只用于局部线条或图标，不铺满背景/大卡片；不会给所有图片统一染色。阴影用很浅的中性灰，主要依靠留白、字号、对齐和细边组织层级。

普通文字目标≥4.5:1、大字号≥3:1，依据[W3C说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。准备阶段核算实色配对，包括辅助字、选中底纹、状态和控件边界；最终透明度、照片叠字、渐变线及实际focus仍需页面实测。浅色装饰边不能冒充满足输入/focus的可辨门槛。

间距采用4/8/12/16/24/32/48/64px；控件圆角12、卡片18、面板24px。正文15px/1.65，辅助12–13px，卡片标题18px；主标题桌面48px、小屏32px。使用本机Arial、PingFang SC、Microsoft YaHei等fallback，中文排版优先，避免外部字体阻塞加载。主按钮高48px，图标/小屏交互目标至少44×44px（项目选择）。

## 布局与构图

桌面内容最大1440px，左右32–48px；列表4列并保留图片呼吸空间，不复制无关工具导航。列表封面3:4，制作详情封面按内容使用16:10，结果完整预览contain。主体焦点/人像脸部/宠物耳部不被裁切；候选照片横图在3:4卡片裁切以人工核对为准。卡片文字优先放在图片下方的白色信息区，不直接叠在高频纹理上；预览背景用浅灰，保留完整图像。

制作页保持约360–400px左面板+剩余历史，gap24；历史卡桌面2–3列。小于900px堆叠，375px页面16px边距，模板可1–2列，历史优先1列保证原因可读；分类横向滚动但不拦截页面竖向滚动。

首页轻量hero左文右图（Orbit/Glow），随后实用模板网格，再接紧凑四页签灵感画廊（Dither/Ripple/Halftone/Pixel）；同屏动效协调详见react-bits.md。画廊不是新的业务路由，主CTA Electric Border短触发。列表引导不扩大成阻挡创作的营销长页；按钮、图片、信息有共同基线。白底不冲淡图片细节；面板/边框保持中性，不用大块深色容器承载特效，不让所有区域都发光。品牌继续“映作”，保留其文字标识并重绘为本项目简单几何标记。

## 组件状态

按钮：idle/hover/focus/pressed/disabled/submitting，禁用使用真实disabled；光晕不替代focus。上传：空位/选图预览/上传中/就绪/失败/替换/移除，提供文字状态。任务：排队/三个Java阶段/成功/执行失败/查询异常。空/加载/请求失败也纳入同一设计。

顶部导航提供一键“动态效果”开关；“动效设置”详细偏好放身份面板中的辅助区，提供跟随系统/静态两档，存本地偏好，不进用户数据库；系统要求reduce时始终静态。它管理视觉运动，不影响任务执行。基础功能在动效库加载失败时仍可操作。


## 页面文案

特效自然融入图片、留白和操作反馈，不在前端加说明性文字。页面不展示组件名、技术名、特效原理、参数或“此处使用……特效”等注释，也不添加“移动鼠标体验”“悬停查看效果”“点击体验动画”等引导。作品画廊以创意、旅行、人像、宠物等内容题材命名，不以特效名或演示名组织界面。

保留品牌、内容标题、导航、操作、上传要求、真实状态/错误、动态效果开关及必要的无障碍名称。暂停和静态控制用简短操作名称，不解释实现。组件映射、参数和验收操作只写在开发文档/取证记录；源码维护注释和第三方许可照常保留。


## 浅色环境下的特效

七项创意保留位置、互斥和降级规则，统一在浅色页面调校。Glow用低饱和蓝紫的极轻局部色晕，alpha目标0.04–0.08且≤0.10；Electric为窄而清楚的蓝紫线段，不带大范围泛光。Orbit图框为白底细边；Pixel粒子小而稀疏。Dither/Halftone的纹理局限图片内部，不能给画廊套黑底或霓虹底。

Canvas/透明层必须与浅色底自然融合，避免黑色清屏矩形、浅色上无法看清的加色混合、过曝和拖影。若效果不适配，先调颜色、混合方式、线宽和范围；不能把整页改暗来适配示例。保持可感知的细节与克制的强度，美学和舒适两门槛均需在浅色实际页面验收。
